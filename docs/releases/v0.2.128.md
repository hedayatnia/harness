# Harness v0.2.128

Desktop release for macOS, Windows and Linux: prompts sent from the phone
start without opening the chat on the desktop, what graff kept out of context,
rendered pages you can see, and sidebar fixes.

## Sending from another device

- A message sent from the iOS app now starts even when its chat isn't open on
  the desktop (#412). The nudge that announces a message could arrive before
  the message itself; the desktop went idle and waited until someone opened
  the chat. A chat woken by a nudge now keeps listening briefly, and a desktop
  sending to another computer nudges it again once its message is on the
  server.
- While a prompt from another device waits to start (not picked up yet, or its
  images still uploading), the desktop shows it as a dimmed message with
  "Sent from another device · waiting to start" or "· waiting for its
  attachments", and the chat is named after it instead of "New session"
  (#415).
- A follow-up typed meanwhile is queued behind that prompt instead of starting
  its own run, and queued messages no longer jump ahead of a prompt that is
  waiting for its attachments.
- When a run starts long after its prompt was sent, the working line shows
  "waited 9m 57s to start" next to the run timer (#413).

## Context

- graff chats show what graff kept out of the model's context next to the
  context meter, for example "45% · 102k saved". Hover for the breakdown:
  tool output kept in files, tokens freed by compaction, and input read from
  the provider's cache (listed, never counted as saved). Needs graff 0.302.45
  or later; other agents show nothing new.

## Rendered pages

- A page the agent renders gets its own visible row that opens it, instead of
  sitting inside a collapsed "Called 1 tool" group, in compact mode too.

## Sidebar and tabs

- The tab list fades at its scroll edges instead of cutting through a title
  (#427).
- Pane cards stay in two compact columns at every sidebar width (#426).
- `/resume` replaces the current tab; global search still opens a tab (#421).

## iOS and Android source changes

- iOS stays signed in across restarts, background token refreshes while the
  phone is locked, and network switches mid-refresh.
- iOS nudges the desktop again once a sent message is confirmed on the server.

Mobile builds are distributed separately; this desktop release does not itself
update TestFlight, App Store or Play installations.
